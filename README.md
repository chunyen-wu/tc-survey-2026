# 減碳技術成熟度曲線專家問卷（第一輪）

環境部氣候變遷署 114 年度補助溫室氣體減量管理及氣候變遷調適研究發展計畫
「減碳技術成熟度曲線構建與碳費投資成效分析」
執行單位：財團法人中華經濟研究院

---

## 這是什麼

以 GitHub Pages 託管之靜態問卷網站，作答資料透過 Google Apps Script 寫入計畫自有之 Google 試算表。
相較於 Google 表單，本作法可呈現真正的表格、將矩陣題之級距定義置於選項格內，並在**不需登入任何帳號**的情況下自動儲存作答進度。

三份問卷共 276 個必答題項：

| 檔案 | 卷別 | 必答題項 | 預估時間 |
|---|---|---|---|
| `core.html` | 核心卷 | 122 | 約 60 分鐘 |
| `ext-h2.html` | 擴充卷（二之一）氫能 14 項 | 44 | 約 20 分鐘 |
| `ext-ccus.html` | 擴充卷（二之二）CCUS 36 項 | 110 | 約 45 分鐘 |

## 檔案結構

```
├─ index.html          填答入口頁（三卷導覽）
├─ core.html           核心卷
├─ ext-h2.html         擴充卷（氫能）
├─ ext-ccus.html       擴充卷（CCUS）
├─ assets/
│   ├─ config.js       【要改這個】收件端網址、聯絡資訊、填答期限
│   ├─ survey.css      樣式
│   └─ survey.js       前端引擎（渲染、自動儲存、驗證、送出）
├─ data/
│   ├─ core.js         【改題目內容改這裡】核心卷題目與技術題幹
│   ├─ ext-h2.js       氫能卷題目
│   └─ ext-ccus.js     CCUS 卷題目
├─ backend/
│   └─ Code.gs         Apps Script 收件端（不放在網站，貼到試算表的 Apps Script）
└─ README.md
```

`.html` 檔只是空殼，內容全部來自 `data/*.js`。修改題目文字只需編輯資料檔，不必動程式。

## 部署步驟

### 一、建立收件端（約 10 分鐘）

1. 建立一個新的 Google 試算表，命名如「專家問卷回覆資料」。
2. 於該試算表點 **擴充功能 → Apps Script**，將 `backend/Code.gs` 全部內容貼入 `Code.gs`，存檔。
3. 點右上 **部署 → 新增部署作業**，類型選「網頁應用程式」，設定：
   - 執行身分：**我**
   - 具有存取權的使用者：**所有人** ← 務必選此項，否則受訪者無法送出
4. 按「部署」，複製產生的網址（格式 `https://script.google.com/macros/s/AKfycb.../exec`）。
5. 回到 Apps Script，上方函式選單選 `testWrite` 並執行，確認試算表出現一列測試資料後**刪除該列**。

> 每次修改 `Code.gs` 後，須重新「部署 → 管理部署作業 → 編輯 → 版本選『新版本』」，否則線上仍是舊版。網址不會改變。

### 二、設定網站

開啟 `assets/config.js`，填入：

```js
endpoint: "https://script.google.com/macros/s/AKfycb...../exec",
contactName:  "王小明",
contactPhone: "(02)2735-6006",
contactEmail: "someone@cier.edu.tw",
deadline: "民國115年10月17日",
```

### 三、發布至 GitHub Pages

1. 建立 repository，**建議設為 Private**（期末報告尚未送審；Private repo 亦可啟用 Pages，惟需 GitHub Pro 或組織方案。若帳號為免費個人方案，Pages 僅支援 Public repo，此時請先確認委託契約之保密條款）。
2. 將本資料夾所有內容（`backend/` 可不上傳）推送至 `main` 分支根目錄。
3. repository 設定 → Pages → Source 選 `main` / `(root)`，儲存。
4. 數分鐘後即可由 `https://<帳號>.github.io/<repo>/` 開啟。

### 四、產生個人化連結

於 Apps Script 中修改 `makeLinks` 函式的 `BASE`（GitHub Pages 網址）與 `CODES`（專家代碼清單），執行後會在試算表新增「個人化連結」工作表，可直接用於郵件合併。

連結格式為 `.../core.html?id=E01`，開啟後受訪者代碼欄會自動填入。

## 上線前務必確認的五件事

1. **送出測試**：以 `?id=T99` 開啟核心卷，隨意填完所有必答題並送出，確認試算表 `core` 工作表出現該列，事後刪除。
2. **自動儲存測試**：填幾題後關閉分頁，重新開啟同一連結，確認作答已回復、頁面底部顯示「已回復 … 之作答」。
3. **手機檢視**：以手機開啟核心卷，確認 Q3 四構面矩陣改為直排、無左右滑動。
4. **遺漏值編碼**：匯出試算表為 CSV，確認「無法判斷」存為 `99`。**分析時須將 99 設為遺漏值，不得計入四分位距與眾數占比。**
5. **題幹事實**：`data/core.js` 之十項重點技術題幹係依報告初稿 v2 之定案值撰寫。若查證清單中之企業查證結果與題幹所載有出入，請於寄發前先修正資料檔。

## 資料格式

試算表每份問卷各自一個工作表（`core` / `ext-h2` / `ext-ccus`），欄位隨題目自動增加。

固定欄位：`收件時間`、`問卷`、`受訪者代碼`、`送出時間(ISO)`、`瀏覽器`

作答欄名＝題號，例如：

| 欄名 | 內容 |
|---|---|
| `B1` ~ `B5` | 專家背景，值為選項代碼 |
| `B3` | 複選題，多值以 `\|` 分隔（如 `1\|5\|6`） |
| `K1-Q1`、`K1-Q2` | 全球／在地 Hype 階段，值為 `1`~`6` 或 `99` |
| `K1-Q3_1` ~ `K1-Q3_4` | 技術潛力四構面（減碳潛力／不可替代性／戰略重要性／成本競爭力），值為 `1`~`4` 或 `99` |
| `K1-Q4` | 商業化時程，`1`~`4` 或 `99` |
| `K1-Q5` | 補助優先順序，`1`~`5` 或 `99` |
| `R1` ~ `R5` | 判定規則檢核，`1`~`5` 或 `99` |
| `P1` ~ `P10` | 政策建議，`1`~`5`（P1 為 `1`~`6`）或 `99` |
| `E-A_1` ~ `E-A_10` | 成效指標可操作性，`1`~`5` 或 `99` |
| `E-B_1` ~ `E-B_10` | 成效指標政策應用性，`1`~`5` 或 `99` |
| `H-S1-Q1` 等 | 擴充卷一般項目，格式同上；`-Q3` 之 `0` 代表「不適合以碳費補助」 |

同一受訪者重複送出會新增一列；分析時取同一代碼之**最後一列**。

## 設計說明

- **自動儲存**：以瀏覽器 `localStorage` 實作，不需登入、不依賴 cookie，換裝置需重填但同一裝置關閉後可續填。每次作答變更即存，並顯示最近儲存時間。
- **送出**：優先以 `fetch` 送出；若遇 CORS 問題則自動改用隱藏表單送出。兩者皆失敗時，受訪者可按「下載作答備份」取得 JSON 檔寄回承辦人，作答不致遺失。
- **驗證**：未完成時列出缺漏題號並可點擊跳至該題，不會讓受訪者盲找。
- **無追蹤**：不蒐集 IP、不使用第三方分析、`robots` 設為 noindex。唯一外連為 Google Fonts（字體）與送出時的 Apps Script 端點。
